\section{Abstract}

Recent deep-learning accelerators adopt ultra-low-precision formats such as
8-bit (FP8) and 4-bit (FP4) to trade numerical precision for throughput and
energy efficiency.\cite{micikevicius2022fp8} Unlike standard IEEE-754
types, these custom formats (e.g., NVIDIA’s E4M3/E5M2 and the new FP4 variants)
encode exponent bias, mantissa length, and NaN/infinity representations
differently, leading to subtle semantic differences across hardware platforms.\cite{kim2025investigation}To support sound verification, we will
mechanize precise, machine-checked definitions of IEEE-floating point in Lean.
This will result in a new floating point mechanization, along with a bitblaster that is integrated with Lean's existing
bitvector library.
This project will use algorithms built on SymFPU,\cite{symfpu}a state of the art floating point bitblasting approach that is used in CVC5 and Bitwuzla
to translate floating point into fixed-point operations,
followed by an encoding of fixed-point operations into bit-vectors.
Overall, this project yields an end-to-end verified solver for the floating point bit-blasting pipeline,
and furthermore, the first end-to-end verification of a SymFPU-style floating point bitblaster.

\paragraph{The Rise of Custom Low-Precision Arithmetic}
The rapid growth of machine learning and high-performance
computing has spurred the development of specialized hardware accelerators that
utilize custom, low-precision floating point formats, such as FP8 \& FP4.\cite{micikevicius2022fp8, kim2025investigation}These formats sometimes
deviate subtly from the well-established IEEE-754 standard, offering significant gains
in computational throughput and energy efficiency at the cost of numerical
precision and introducing subtle semantic variations.
For example, the E4M3 format does not represent infinities,\cite{micikevicius2022fp8}
and NaN values have a single bit pattern allowed.
This allows for seven more magnitudes to be represented (256, 288, 320, 352, 384, 416, 448) compared to an IEEE-754 compliant version ---
a trade off of compliance for range.

Verifying designs incorporating these novel arithmetic types presents a significant challenge, requiring
precise, formal semantics and reasoning techniques tailored to their specific behaviours.
Effectively applying bit-blasting techniques (a common strategy in SMT solvers for converting arithmetic problems into boolean satisfiability)
benefits formally verified translations from these low-precision semantics to SAT queries.
Our work addresses this need by providing mechanized semantics for floating point,
and developing verified bit-blasting procedures.
This paves the way for formally verified solvers for formats that \emph{slightly deviate} from IEEE-754,
as mild pre/post processing steps of the IEEE semantics,
thereby enabling trustworthy verification of cutting-edge floating point formats.


\paragraph{Floating Point Solvers}
Solvers for floating point have received a lot of attention,
as they are a key component of hardware verification
Floating point verification by bitblasting has proven to be effective in practice,
with CBMC being one of the first solvers to use this technique.\cite{cbmc,brillout2009mixed}This approach is also adopted by SymFPU, the floating point solver that is used by CVC5 and Bitwuzla
in order to convert floating point problems into bitblastable SAT problems.

\paragraph{Our Preliminary Work.}

Our preliminary work provides the essential building blocks for the proposed
research, focusing on high-assurance foundations for hardware verification
using formal methods in Lean.
We have made significant contributions to the Lean bitvector library,
implementing circuits necessary for bitblasting fixed-width bitvector operations (e.g., subtraction, multiplication, division, modulo).
We have also added support for overflow flags by mechanizing efficient overflow detection circuits.\cite{gok2001efficient}
We are developing a formally verified floating point bitblasting
library for Lean, targeting low-precision formats such as 8-bit (FP8) and
4-bit (FP4).\cite{fplean} These custom formats, used in modern deep learning accelerators,
deviate from the standard IEEE-754 and require precise formal semantics.\cite{micikevicius2022fp8, kim2025investigation}
Our preliminary work includes mechanizing these semantics
and developing an \emph{unverified} bitblasting engine that systematically translates
FP8/FP4 operations into SAT.
We have tested that this engine produces the correct floating point encodings by
performing a golden test against known-good software floating point implementations.

While this provides a working library, it is not certified correct;
We now aim to verify its correctness end-to-end,
beyond simply performing testing against known-good implementations.

\section{Methods}

Our methodology is to extend our new floating point library in Lean
with end-to-end proofs of correctness for the bitblasting pipeline.
This involves four main components:

\paragraph{Mechanization of Fixed-Point Arithmetic.}
A key component of our approach is the mechanization of fixed-point arithmetic in Lean.
Lean has begun to develop a theory of dyadic rationals,\footnote{\url{https://github.com/leanprover/lean4/blob/master/src/Init/Data/Dyadic.lean}} (numbers of the form $n/2^k$ for integers $n,k$)
which serve as the mathematical foundation for fixed-point representations.
We will build on this theory to define fixed-point operations for all IEEE-754 operations,
including division and square root.
Furthermore, development is necessary to define rounding modes correctly,
and to get a representation of floating point rounding modes in terms of fixed point.

\paragraph{Verified Circuits for Fixed-Point Arithmetic.}
Building on the existing bitvector library in Lean,
we will mechanize the circuits that encode fixed-point arithmetic as bit-vectors.
Fixed point operations that mirror floating point operations (e.g., addition, subtraction, multiplication, and division)
will be implemented as bitvector circuits.
Each operation will be accompanied by proofs of correctness,
showing that the bitvector circuit correctly implements fixed-point semantics.

\paragraph{Reduction from Floating Point to Fixed Point.}
Following the SymFPU approach,
we will mechanize the floating point semantics as a preprocessor that handles 
NaN/infinity cases, normalizes denormal numbers, and reduces floating point operations
to fixed-point operations. 
Following this, we will use the mechanization of fixed-point arithmetic to complete the bitblasting pipeline.
The most complex step in this stage is the careful handling of rounding (e.g., division and square root needs nontrivial bounds).

\paragraph{Integration with \bvdecide{} and \leanwuzla{}}
Finally, we will integrate all of these components,
writing frontends for both \bvdecide{} (Lean's bitvector SMT solving tactic) and
\leanwuzla{}\cite{leanwuzla}(A CLI wrapper around \bvdecide{} that consumes SMT-LIB benchmarks).
This enables end-to-end verification of floating point benchmarks both in the SMT-LIB format, as well as within Lean itself.

\section{Expected Results}

We expect to have a formalization comprising of the following components:
(a) a mechanization of fixed point arithmetic, built on top of the dyadic rational 
theory that is being built in Lean core,
(b) a mechanization of fixed-point arithmetic circuits in bit-vectors, building on Lean's existing bitvector library,
(c) a mechanization of the reduction from floating point to fixed point arithmetic, following the SymFPU approach,
(d) an integration of all of these components, giving an end-to-end verified
floating point bitblasting pipeline for floating point.
Finally we will also package all of these into an executable extension of Leanwuzla and a 
tactic extension of \bvdecide{} to enable floating point reasoning natively in Lean.
